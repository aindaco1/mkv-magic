# MKV Magic 0.2.2 beta

MKV Magic 0.2.2 prevents verified outputs from reaching the final commit
without a writable destination grant and makes privacy-safe commit failures
specific enough to diagnose without exposing user paths.

## Highlights

- Beside-source output remains preferred, but it runs automatically only when
  macOS provides a live directory grant. Otherwise MKV Magic opens the normal
  save panel before processing begins.
- Batch subtitle cleanup and saved-workflow queueing now require one explicitly
  selected or remembered writable output folder before their action is enabled.
- Collision-safe numbering still selects a distinct filename and never
  overwrites an existing output.
- Privacy-safe reports distinguish unavailable destinations, existing outputs,
  denied commit permission, unsupported no-overwrite filesystem operations,
  other commit failures, and History-write failures without including paths,
  filenames, errno values, or raw errors.
- Lossless Join now compares structured codec-initialization hashes in addition
  to visible stream properties. When that is the only technical mismatch, Join
  offers a verified zero-encode repair before the one-generation Common Format
  fallback. For H.264, MKV Magic applies a packet-copy header filter and remuxes
  the video lane so each Part keeps its own decoder headers and packet cadence,
  while preserving the
  first Part's track identity. The result is committed only after every boundary
  decodes cleanly and its packet payloads, tracks, chapters, duration, original
  sources, and reopened output all verify.
- Common Format can now treat reviewed HD-or-larger untagged 8-bit H.264 Parts
  as SDR and write an explicit verified BT.709 output. This does not relax the
  blocker for 10-bit, HEVC, SD, HDR-signaled, or conflicting color facts.
- Select multiple inspected files and choose **Tags…** to review one batch,
  select one output folder, and remove all global and track tags from every
  ready MKV. Each output is verified independently; tag-free or unsupported
  files are skipped and originals remain unchanged.
- Join Files automatically places every rebased source leaf chapter in one
  player-compatible top-level list. The former hierarchy choice is no longer
  shown because consumers that display only Part parents can hide the actual
  chapters. Every join route uses the same canonical composer, review count, and
  output audit. Repeated same-style consecutive sequences such as `Chapter 1…42`,
  `Chapter 1…43`, and `Chapter 1…46` are continued as `Chapter 1…131`; mixed,
  descriptive, and nonconsecutive names are not rewritten.

## Encoding and compatibility

- Requires macOS 13 Ventura or newer and remains one Universal app for Apple
  Silicon and Intel Macs.
- Bundles MKVToolNix 101.0 and FFmpeg 9.0.1 as native `arm64` and `x86_64`
  slices.
- Mounted-DMG verification now runs the app and embedded tools only in the
  host's native architecture by default. Intel acceptance remains a physical
  Intel-Mac gate; forcing a Universal component through Rosetta is no longer a
  normal QA step because it causes macOS to record a misleading Intel-support
  warning.
- Metadata edits, truly compatible joins, remuxes, subtitle cleanup, and tag
  export/removal remain zero-encode operations. Differing decoder initialization
  can now use the reviewed lossless header repair when no other technical
  mismatch exists.
- A MKVToolNix warning is never treated as proof of success. MKV Magic discards
  the temporary output if strict boundary decoding or any packet/structure audit
  fails; the user can uncheck lossless repair to use Common Format once.

## Safety and privacy

- Originals are never overwritten. Each output is created in private temporary
  storage, verified, committed to a distinct authorized destination, and
  reopened before success is reported.
- MKV Magic runs locally, with no accounts, telemetry, uploads, remote media
  APIs, or LLM dependency. Updates remain manual-only.
- Diagnostic categories are allowlisted and coarse. Reports continue to omit
  media contents, paths, filenames, titles, subtitle text, bookmarks,
  credentials, persistent identifiers, exact timestamps, and raw tool output.
- A join that fails strict boundary decoding exports the fixed
  `joinBoundaryDecodeFailed` category and a validated one-based boundary number;
  it does not export the decoder exit code or diagnostic text.

## Current limitations

- A batch uses one selected or remembered output folder rather than silently
  attempting to write beside multiple independently selected source files.
- Batch tag removal runs files sequentially with measured item progress and
  per-file failure isolation, avoiding competing full-file clones on the same
  disk.
- Filesystems that cannot perform the required atomic no-overwrite commit remain
  unsupported and now produce a distinct privacy-safe category.
- Image-subtitle OCR is not included.
- Activity remains indeterminate when no trustworthy duration, byte, frame,
  stage, or item denominator exists.

## Requirements

- macOS 13 Ventura or newer on Apple Silicon or Intel.
- Enough free disk space for the verified output and temporary work.
- User-selected read/write access to every source and output directory.

## Candidate acceptance

This candidate remains a draft until its exact downloaded DMG passes a
clean-account Apple Silicon install and launch, a physical Intel install and
launch, the prior-version Sparkle replacement and relaunch check, the packaged
fixture with original-preservation verification on both architecture slices,
and real-file playback verification in Jellyfin/Plex.
