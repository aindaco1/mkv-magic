# MKV Magic 0.3.0 beta

MKV Magic 0.3.0 adds reviewed batch tools, durable queue recovery, appearance
settings, app-wide output defaults, and optional in-app problem reporting.
These notes describe the 0.3.0 source. Installer verification and hardware
acceptance must identify the exact candidate artifact.

## Highlights

- Folder remux reviews multiple videos and matched text subtitles, then creates
  one independently verified, zero-encode MKV per included video. Bulk track
  metadata edits, text-subtitle extraction, relative Fast Trim, tag removal,
  subtitle cleanup, and chapter suggestions share the existing review and queue.
- Output defaults cover media and small exports. Automatic destinations use
  unused filenames and retained folder grants; Ask Every Time remains explicit.
- Help > Report a Problem previews bounded, sanitized diagnostics before an
  explicit send through a separately sandboxed reporting helper.
- Lossless Join can review a zero-encode H.264 header repair when decoder
  initialization is the only technical mismatch. Strict boundary decoding,
  packet-payload comparisons, structural verification, and original preservation
  remain required. Common Format may treat explicitly reviewed HD-or-larger
  untagged 8-bit H.264 as SDR; ambiguous or conflicting color facts stay blocked.
- Settings now offers **System**, **Light**, and **Dark**. System is the default
  and follows macOS automatically. Shared high-contrast grayscale text and a
  neutral native accent keep attention on the media; warnings and errors retain
  restrained color. Explicit macOS accent preferences remain respected.
- The inspector gives details more room, keeps common actions visible, and puts
  remaining operations in expandable, scrollable **More Tools**. Title edits
  validate while typing; changing an accepted title requires a fresh preview.
- Preparation failures no longer vanish on an ordinary refresh. Workflow review
  distinguishes **Will apply** from **Already satisfied** without implying an
  error or completed execution. Inspector and workflow-review tag counts match
  the shared tag-action policy. Finished preparation and cancelled reviews clear
  stale progress text; More Tools keeps its arrow and accessible name accurate.
- Trim previews and Chapter Studio thumbnails handle limited-range video as
  full-range JPEGs. Trim samples no longer seek past the last available frame.

- Concurrent jobs share one serialized History writer, preventing parallel
  Clean MKV operations from losing lifecycle records or failing while recording
  verification and commit. Media processing itself remains concurrent.

- **Clean MKV** now opens the complete zero-encode cleanup recipe from the main
  window even when no subtitle removal is suggested. It reviews applicable
  title, tag, image-attachment, track-role/name, filename, and subtitle changes,
  explains steps that are already satisfied, and supports a selection of MKVs
  through the existing per-file batch review.
- The track editor no longer clips its language label or stretches individual
  rows. Live validation enables Preview Changes for a valid changed name,
  language, or flag and points to Verify & Run to save the verified copy.
- The sidebar now uses clear Create, Tools, and Jobs groups. Every destination
  is a real button; only Join Files is unavailable until its media prerequisite
  is met.
- History job details use an appearance-aware, selectable plain-text view.
- Help, licenses, and both join reviews use that same text layout so their
  documents remain readable and fill the viewport on older macOS releases.
- Drag exactly one compatible MP4, M4V, MOV, or chapter-free WebM with one SRT,
  ASS, or SSA to review a single **Remux Video + Subtitle…** operation.
- Existing audio language metadata is preserved. Otherwise, conservative
  trailing filename language markers propose editable audio and subtitle
  defaults before the remux.
- The remux copies all source media packets, adds the reviewed subtitle in one
  `mkvmerge` pass, verifies the exact subtitle payload and copied packets before
  and after commit, and leaves both inputs unchanged. MP4/Matroska duration
  rounding uses one shared 100 ms bound for the copied media and appended
  subtitle; the verifier still rejects anything beyond that bound.
- The accepted two-file review enables **Add to Queue** as well as immediate
  execution. Multiple pairs remain as independent waiting jobs, and each private
  job retains the reviewed audio and subtitle language choices.
- Automatic starts refill the queue after each completed batch, including the
  single lightweight slot allowed on battery. Every refill reuses admission,
  source/output checks, Pause, and fresh power/thermal conditions; failed jobs
  still require review rather than being retried automatically.
- A failed queue item now explains its coarse failure stage and privacy-safe
  category in a selectable **Selected Job Details** section. Optional support
  reports include the same bounded queue diagnosis without filenames, paths,
  subtitle text, custom workflow names, raw tool output, or exact timestamps.
  A freshly reviewed retry keeps the same row and increments its attempt count
  only when execution actually starts.
- Selecting multiple files now offers **Suggest Chapters…**. One stable options
  sheet runs local scene/black/silence analysis independently, one combined
  checklist identifies every timestamp's source, and ready MKVs become separate
  collision-safe verified chapter copies while originals remain unchanged.
- Joined source chapter leaves remain in one player-compatible timeline, with
  repeated consecutive numbered sequences continued across Parts.
- Universal verification stays native to the host so Apple Silicon QA does not
  itself trigger macOS's Intel-component warning.

## Encoding and compatibility

Compatible remux, metadata, subtitle, chapter, and lossless join operations avoid
video encoding. Where conversion is necessary, the reviewed plan permits at most
one video generation. Encoder choices depend on successful local capability
probes; hardware acceleration and speed vary by Mac. Supported SDR/static-HDR10
paths retain their declared verification rules rather than treating unknown
dynamic-range metadata as universally safe to transcode.

## Safety and privacy

- Originals are never overwritten. Output is prepared privately, verified,
  committed atomically to a distinct destination, and reopened. Optional
  Trash-after-verified-success requires explicit selection and a verified output;
  otherwise originals stay in place.
- MKV Magic runs locally with no accounts, telemetry, remote media APIs, or
  runtime LLM dependency. The main app and media tools have no network access.
  An explicit, reviewed support submission uses the isolated reporting helper
  and fixed relay; it sends no media, raw logs, or private paths. Updates remain
  manual-only. Jev evaluates public synthetic evidence only in developer tests.
- Filename language inference is deliberately conservative and always editable.

## Current limitations

Reviewed folder remux now supports multiple confident text sidecars per video;
bulk track-role edits, text-subtitle extraction, and beginning/end Fast Trims
share the durable queue. See the [batch audit](../testing/BATCH_ACTION_AUDIT.md)
for bounds and review contracts. Image-subtitle OCR, external audio addition,
arbitrary elementary-stream extraction, batch exact encoding, timeline chapter
dragging, general splitting, and attachment add/replace remain separate roadmap
work. Image-subtitle OCR is not included. Clean MKV still uses an English-library-oriented recipe;
review the proposed language and subtitle changes before running it. The
[product review](../testing/UX_PRODUCT_REVIEW_2026-09-05.md) distinguishes current
flows from the larger original scope.

## Requirements

macOS 13 Ventura or newer, on Intel or Apple Silicon. The Universal app includes
native media tools for both architectures; no separate Homebrew or MKVToolNix
installation is needed. Test candidates are not public-release acceptance;
the signing/notarization status of the exact installer must be recorded.

## Candidate acceptance

The latest documented private Intel-test candidate is **0.3.0-test.21**, build
**1788818173**. It is signed and Universal, but unnotarized and unpublished.
Its [artifact ledger](../testing/BATCH_ACTION_AUDIT.md) records exact checksums
and the checks performed on that build. Use the
[Intel sample checklist](../testing/INTEL_TEST_CHECKLIST.md). Those results do
not cover later source changes or a future public installer.

The September 22 development check passed source/security checks, the Universal
build, 891 Swift tests (one optional private-media skip), 19 evaluator tests,
48 labeled Jev examples, and all 12 workflow reviews. The
[Jev validation record](../testing/JEV_EVALUATION.md) explains evidence scope.

**Restored queue access, test.17:** admission now retains the validated bookmark
URLs instead of normalizing them a second time after temporary access ends.
The old path reproduced an FFprobe sandbox denial; retaining those URLs restores
access without changing entitlements. See the
[signed queue regression](../testing/RESTORED_QUEUE_ACCESS_REGRESSION.md) for
exact evidence and remaining installed-app acceptance. The signed candidate
passed an actual GUI cold-relaunch remux without reselecting inputs, with Tries 1,
a complete persisted History lifecycle, three expected tracks, and unchanged
source hashes. Same-session success or ordinary unsandboxed tests alone do not
prove cold-relaunch access.

This candidate is not a public release. The exact packaged DMG still requires
clean-account Apple Silicon install and launch, physical Intel install and
launch, prior-version updater replacement and relaunch, and real-file playback
acceptance before publication.
